# Canadian Coin Collection

Personal checklist of Canadian special and commemorative circulation coins. Open `index.html` with the bundled files or use GitHub Pages; no build step is needed.

## Coin stories and random discovery

Every checklist coin and standard reference has a shareable page at `coin.html?id=<stable-id>`. `stories.js` contains English issue, occasion, reverse-design and variant notes, with source links. Years are used unless a specific release date is documented; known differences between a coin date and its circulation release are explained in the issue note. These are concise original summaries rather than copied source descriptions.

The header's Random coin button samples all 174 checklist entries, excluding references. On a story page it excludes the current coin. `collection.js` shares the existing `alex-coins-v1` storage format and ownership migrations between both pages; standard references never contribute to progress. Photos retain their existing credits and reverse-only crops.

## Weekly discovery and personal website approval

The **New coins** button on the website opens official Mint announcements, without a GitHub login. Check the official source, confirm the coin year/name/denomination and actual circulation colour/non-colour variants, and select **Add to my checklist** or **Skip**. Accepted variants start Missing and join denomination/category filters, totals, random discovery and individual story pages. A skipped announcement stays skipped across sessions; Previous decisions → Review again brings it back. There are no fabricated example coins in the public feed.

`new-coins.js` loads accepted release snapshots before rendering the catalogue. Stable `new-<announcement-id>-<variant>` IDs cannot collide with existing numeric coin IDs. The existing ownership snapshot and its local recovery copy also contain release decisions and accepted coin metadata. Download/Restore backup includes them, including both true and false owned selections; old ownership-only backups still work. Personal choices are not sent to GitHub, Mint or another user, and are not account/cloud synchronization. Clearing website data removes local decisions unless restored from a backup.

Announcements are not a verified catalogue: exact reverse photos and detailed design stories may still need research. Announcement photos are labelled as such; newly accepted cards link to the original Mint source instead of substituting an unverified colour variant or collector photograph. The confirmation explicitly excludes silver and collector-only issues. Duplicate name/year/denomination/variant additions are rejected. Colour/non-colour availability is chosen after checking the source, never invented automatically.

`.github/workflows/check-releases.yml` checks the two official Mint sources every Monday at 14:17 UTC; Run workflow starts it manually. It runs discovery/ownership tests then `check-releases.py --publish-feed`. The short-lived workflow token has contents:write solely to publish `new-coins-feed.json` on the separate `release-feed` branch; the script never writes the shared catalogue or user decisions. No issue is needed for personal approval. The previous `--publish` issue-review mode remains available for maintainers but is not scheduled.

The website reads the public announcement feed from that branch with CORS; this avoids GitHub-token commits failing to trigger a Pages build. It falls back to the bundled last successful feed and clearly labels the date and unavailable live feed. Previous candidate announcements remain in the feed so an older release can still be reviewed even after leaving the Mint homepage. Open/closed issues are irrelevant to personal decisions. A source failure fails visibly rather than claiming no new coins. The initial live check on 31 October 2026 found no new candidate pages outside the existing reviewed baseline.

`node test-collection.cjs`, `node test-new-coins.cjs` and `python3 test-release-watch.py` cover existing selection compatibility, personal additions/skips, session persistence, complete backups, invalid import rollback, duplicate rejection, feed source scope and first-branch publishing. The local fixture used for UI testing is outside the repository and never published.
